# Данные бенчмарка: где что лежит и почему

Решение владельца готово к исполнению. Короткая версия: **код — в публичном репозитории,
сырьё — не покидает прод, обезличенный корпус — в приватном хранилище, и между ними —
гейт, который вручную не забывают.**

## Требования

1. Репозиторий бенчмарка публичный — код должен быть виден извне.
2. Данные содержат персональные данные (имена, резюме, зарплаты) — течь недопустима.
3. Результаты должны быть воспроизводимы: отчёт «модель A лучше B на 100 промптах»
   бесполезен, если завтра промпты другие.
4. CI публичного репозитория должен работать без секретов — иначе чужие PR не проверяются.
5. Новых вендоров и новых ключей — по возможности не добавлять.

## Варианты, которые вы предлагались

| Вариант | Вердикт | Почему |
|---|---|---|
| Временно приватный репозиторий, потом сделать публичным | **Нет** | Git-история вечна. День открытия репозитория — и есть момент утечки: вычистить историю по всем веткам (git filter-repo + force-push) можно только с ошибками, а закэшированные копии и следы в событиях GitHub не откатить. Открытие приватного репозитория — необратимая операция, её нельзя «проверить на стейджинге». |
| Google Drive / Google Sheet со ссылкой | **Нет, как основа данных** | Таблица живая: её меняют руками, экспорт каждый раз разный → бенчмарк невоспроизводим. Ссылка «доступ по ссылке» расширяется в один клик — типовой вектор утечки. Пригодно для рубрик, заметок и чек-листов судьи, но не для корпуса. |
| Облачный бакет (Google Storage / S3) | **Пока нет, оставить в плане** | Сам по себе бакет — хорошее долгосрочное место (версионирование объектов, IAM). Но он даёт новый ключ доступа (service account) там, где уже работает токен GitHub, и заводит второго вендора. Корпус сейчас — 470 КБ: бакет ради 470 КБ — это цена без выигрыша. Вернёмся, если корпус вырастет до десятков мегабайт или появятся бинарники (аудио интервью, сканы). |
| Закрытый репозиторий в другой компании | **Нет** | Персональные данные уходят за периметр в чужую юрисдикцию (152-ФЗ), и каждая поломка теперь чинится через чужую команду. Единственное достоинство — «их ничего страшно», но и своё приватное репозиторий ничем не хуже. |

## Что выбрано: три слоя

**Слой 1 — сырьё. Не покидает прод вообще.**
`/home/vova/agent-data/hh/conversation-history.jsonl` (сейчас 1025 записей, 21 МБ).
Сбор корпуса читает файл **через stdin** (`ssh vm "cat …" | node scripts/extract-corpus.mjs`),
на диск попадает только уже обезличенный результат. Копию сырья никуда не переносим —
значит, и ключ доступа к нему заводить не нужно.

**Слой 2 — обезличенный корпус. Приватное хранилище, версия по sha256.**
Отдельный приватный репозиторий `trained-assist/conversation-bench-data` (создаётся по этому же
плану). В нём `corpus.jsonl` + `prompts/` + `manifest.json` с sha256. Публичный репозиторий
к нему не подключён — только знает, что он существует: загрузчик `src/dataset.mjs` умеет
работать с любой из трёх подключек (`BENCH_DATASET_DIR` / `BENCH_DATASET_REF=owner/repo#subdir` /
будущий URL), а **sha256 сверяется в любом случае**: подменённый или отставший корпус ломает
загрузку с ошибкой, а не тихо портит сравнение моделей.

**Слой 3 — публичный репозиторий. Код + синтетический пример.**
`trained-assist/conversation-bench`: скрипты, тесты, `fixtures/` с выдуманными данными (почта,
телефон, имена — фиктивные) и `models.json`. CI гоняет тесты и гейт на фикстурах, без секретов.
Чужой контрибьютору этого достаточно, чтобы поднять прогон на своих моделях.

## Как утечка перекрывается дважды

1. **Псевдонимизация** (`src/pii.mjs`): словарь имён собирается **по всему корпусу за два
   прохода** (иначе имя, встречающееся только в ответе, осталось бы), закрывает словоформы
   («Иван» → «Ивану/Иванова»), почты/телефоны/telegram/ссылки → токены, зарплата округляется
   до шага 10 тыс. (сам факт зарплаты остаётся — он нужен для оценки письма).
2. **Гейт** (`scripts/scan-pii.mjs` + CI): строгий детектор ищет остатки **после**
   обезличивания и блокирует PR. Плюс CI отдельно проверяет, что в git не попал сырой JSONL.

Гарантия честная: псевдонимизация не убирает все квази-идентификаторы — город, опыт в
Wildberries 50 месяцев и зарплата остаются (без них бенчмарк не имеет смысла: письмо должно
реагировать на факты). Поэтому реальный корпус по умолчанию **не публикуется**: он лежит в
приватном слое, а решение «выпускать эту выборку наружу» принимается владельцем по конкретному
датасету, а не «настройкой в коде».

## Проверено на реальном проде (04.10.2026)

Прогон по 100 последним реальным записям: телефонов, почт, ссылок, ФИО — **0**; масок имени —
3131; гейт чист. По дороге нашлись и закрыты три реальных бага, которые на выдуманных
фикстурах не ловились — каждый закрыт регрессионным тестом:

- `\b` в JavaScript не видит кириллицу — и словарь имён, и гейт пропускали русские ФИО;
- собранные регулярки шли без флага `u` — `\p{L}` читался как буква «p», гейт слепо считал
  цифры внутри хешей ИНН-ом;
- словарь имён собирался по полям, а не по корпусу — «Олег, спасибо…» из ответа прода
  оставался в тексте.
